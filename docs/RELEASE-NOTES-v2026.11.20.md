# padavan-tw v2026.11.20（第一個正式版，草稿）

> 草稿：標「待補」的項目要等 2026-11-19 夜間長測與 5G 出廠預設確認的數據，早上填入後才發布。

支援機型：**Newifi D3**（`NEWIFI3`，Breed 刷入）、**小米 CR6608**（`CR660x`）。每個機型有標準版（880 MHz）與 `-oc1000` 超頻版（1000 MHz）；不確定就用標準版。刷機前請比對 `SHA256SUMS`。

## 重點

### Wi-Fi 穩定性
- **修正 2.4G 每隔一陣子中斷約 50 秒**（D3）：根因是 4.4 核心新配置的 skb 沒有清掉硬體 NAT 的殘留標記，本機送出的封包被誤送進 PPE，有線埠的 STP 封包變成「2.4G 收到自己的封包」而被判定迴圈。修正後同條件 60 分鐘 0 次（修正前 30 分鐘 2 次）。已回報 TurBoTse/padavan#33、hanwckf/padavan-4.4#73
- **Wi-Fi 重新啟動後立刻恢復連線**（急速連線）：原本 STP 要等 30 秒，裝置在這段時間連上會拿不到 IP（Windows 顯示「沒有網際網路」好幾分鐘）。STP 計時也縮短成 8 秒
- **Wi-Fi 迴圈保護**：Wi-Fi 介面的 STP 封包預設擋掉；某個頻段收到其他裝置的 STP 封包（家裡有橋接器、中繼器）時，只有那個頻段自動改回標準保護，並寫進系統記錄
- 5G 頻寬 40／80 MHz 時自動選頻不選 165（選到會掉成 20 MHz）；國碼台灣時 2.4G 自動選頻不選 12、13
- 5G 出廠預設值：待補（TxBurst、Greenfield 的確認結果）
- 沒有原廠 TxBF 校正資料的機型（例如 D3）不再顯示 TxBF 選項（設了也無效）

### 網路
- **自動 NAT66**：接在另一台路由器後面、上一層沒有可分配的 IPv6 前綴時，區網自動改用 NAT66（網際網路頁可關閉）
- **igmpproxy（MOD）**：修正群組過期時當機（use-after-free，上游 PR #98 的修法）；區網送出的群播不再被當成上游來源
- 黑潮 DNS **3.3.7**：路徑檢查（分辨上游壞了和路上有人動手腳）、一般 DNS 被接走時不再拿來評測、沒有 IPv6 時不再試 IPv6 上游；路由器 IPv6 關閉時自動告訴黑潮

### 其他
- 刷機寫完由 init 直接重開，不再卡在「重開中」
- 硬體 QoS（QDMA）捨棄：實測 CPU 約 3 倍、延遲沒有改善
- 診斷頁新增「Wi-Fi 迴圈保護」開關

## 已知限制
- Linux 4.4 核心已停止官方維護，不建議把管理頁面或 SSH 開放到 WAN
- 閉源 Wi-Fi 驅動沒有空中時間公平（airtime fairness），多台裝置同時滿載時延遲會變高
- 部分 USB Wi-Fi 網卡（例如 AIC8800）在 D3 上大量上傳時可能斷線（3.4、4.4 都會，驅動相容性問題）
- 夜間長測結果：待補
