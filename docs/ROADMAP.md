### E2. 智慧模式（自動在硬體 NAT 與 SQM 之間切換）

SQM 與硬體 NAT **都常駐**，控制器只決定封包走哪一條路；狀態存在記憶體。

| # | 項目 | 狀態 |
|---|---|---|
| E2.1 | hw_nat 小修改：執行中開關 `bind_enable`（`/sys/module/hw_nat/parameters/`）。綁定門檻暫存器最大 65,535 pps，擋不住全速 Gigabit 單一連線（約 83,000 pps），所以要改程式 | 📋 |
| E2.2 | 控制器狀態流程（見下表） | 📋 |
| E2.3 | 學習壅塞時段：學到的時段內不嘗試回硬體 NAT | 📋 |
| E2.4 | 每次切換寫入事件時間軸，網頁看得到原因與前後延遲 | 📋 |
| E2.5 | 實機驗證：模擬遊戲 UDP 流量下切換 100 次，最長中斷 < 200 ms、對外 IP 與連接埠不變、0 斷線；不合格就退回「固定時段」 | 🔬 |

控制器狀態流程：

| 狀態 | 檢查頻率 | 離開條件 |
|---|---|---|
| 硬體 NAT（平常） | ping 每 10 秒 | 一次偏高（基準 +30 ms）→ 確認中 |
| 確認中 | ping 每秒、10 秒 | 10 次中 7 次偏高且 WAN 流量 > 方案 70% → SQM；否則回平常 |
| SQM（整形中） | cake 統計每 5 分鐘 | 至少 30 分鐘；連續 3 次檢查都沒有排隊、沒有丟包、流量 < 整形速率 50% → 試放寬 |
| 試放寬 | 60 秒 | 仍走 CPU，cake 速率暫時拉到方案 100%：延遲正常 → 回硬體 NAT；延遲上升 → 回 SQM，30 分鐘內不再試 |

保護：每小時最多進入 SQM 2 次；進 SQM 時清硬體表（已經在壅塞，掉幾個封包可接受），回硬體 NAT 只開放綁定、不清表（零掉包）。

### E3. 簡易模式

| # | 項目 | 狀態 |
|---|---|---|
| E3.1 | 問答式設定：連線方式（光世代 PPPoE／VDSL／有線電視寬頻／固定 IP）→ 封包額外開銷；用途（遊戲、視訊、影片、大量上傳）→ 優先分類與 ack-filter；裝置數與 P2P → 依裝置公平分配 | 📋 |
| E3.2 | 自動取得最大流量：使用者在電腦上用 speed.hinet.net 測速時，路由器從 WAN 硬體計數器同步記錄；另外被動學習一週尖峰（第 95 百分位） | 📋 |
| E3.3 | 整形速率＝實測 90%，且不超過 CPU 處理上限（見 F2）；超過時建議改用 OC 版 | 📋 |
| E3.4 | 進階模式保留所有原始選項 | 📋 |

### E4. 台灣專用自適應演算法（研究）

| # | 項目 | 狀態 |
|---|---|---|
| E4.1 | 自適應速率（參考 cake-autorate）：延遲正常且接近滿載時慢慢調高、延遲上升時按比例調低；上傳與下載分開調整 | 🔬 |
| E4.2 | 多點反射：HiNet 閘道、HiNet DNS、TWNIC、Cloudflare 台北節點取中位數，單一節點異常不影響判斷 | 🔬 |

| E4.4 | 業者特性預設：光世代延遲穩定、基準低；有線電視寬頻上傳窄、晚上 CMTS 壅塞，晚間自動降速；行動網路（4G／5G 備援）頻寬變動大，一律自適應 | 🔬 |
| E4.5 | 依行為分類而非埠號清單：小封包、低速率的 UDP 視為遊戲或語音，標記到 cake 的 Voice 類別 | 🔬 |
| E4.6 | 台灣時段模型：晚上 8 點到 11 點、週末尖峰的預先整形 | 🔬 |
